# 言行 V0 候选模型供应商审查（G2 前置）

审查日期：2026-09-04  
审查范围：`qwen-turbo`、`deepseek-v4-flash`、`MiniMax-M3` 及本轮实际使用的 API 服务  
结论状态：**G2 阻塞／不通过**

## 1. 审查边界

本报告只使用供应商官方公开页面和仓库内已完成的合成 dev 评测产物，不登录供应商控制台、不读取 API Key、不调用模型，也不运行 48 条冻结 test。公开页面的描述不替代法务意见、双方签署的 DPA、控制台实际配额或供应商书面承诺。

各字段使用以下四种证据状态：

- **官方公开明确**：官方页面对当前问题给出直接且可引用的答案；
- **官方公开但含糊**：有相关条款，但范围、期限或适用对象不足以支持生产判断；
- **未找到公开承诺**：本次审查的官方公开资料中没有找到所需承诺；
- **需商务／DPA 书面确认**：仅靠公开页面不足，必须由供应商补充有约束力的答复。

## 2. G2 结论

当前不能确定主生成模型、主校验模型或降级模型，也不能把任何候选注册为产品默认模型。阻塞原因如下：

1. 阿里云官方已把 `qwen-turbo` 列入“旧版模型”，并明确说明旧版模型“不再作为首选推荐”；其公开页面未给出当前具体单价、RPM／TPM 或停止销售／停止服务时间。
2. DeepSeek 当前公开隐私政策明确排除“开发者使用开放平台开发的下游系统或应用中的最终用户个人数据”，因此该政策不能证明下游 API Prompt／Output 的训练使用、保留、删除和处理者义务；同一政策对其适用范围内的数据又包含训练和改进模型的用途。
3. MiniMax API 隐私政策会处理 Services Input & Output，但“不会用个人数据训练以画像或定向消费者”不是“API 输入输出绝不用于训练”的完整承诺；政策还允许将个人信息去标识／匿名化后形成数据库并进行挖掘、分析和商业利用。
4. DeepSeek 与 MiniMax 均未在本次公开资料中给出 API Prompt／Output 的固定保留天数；阿里云只承诺对话数据保留在提供服务所必需的最短时间，仍没有具体天数。
5. 80 条冻结数据中的 32 条 dev 已用于初筛，48 条 test 尚未运行。dev 人工生成偏好为 DeepSeek 与 MiniMax 3∶3，不能据此宣布单一赢家。

产品负责人随后选择 MiniMax-M3 作为下一阶段开发模型。该选择用于推进产品侧 Adapter 与本地安全链路，不改变本报告的 G2 阻塞结论，不构成生产合规批准，也未授权运行 48 条冻结 test 或发送真实用户数据。

2026-09-05 的首次单独授权产品 smoke 只使用全新本地测试账号和合成文本：普通初稿请求成功，但结构化 OOC 校验不可用并安全关闭；确定性高风险旁路通过且没有调用供应商。旧 draft 对失败 OOC 校验内部重发一次的问题随后已改为 0 次重试，JSON 解析边界和结构失败 Token 累计也已加固。历史 Run 的 Token 字段只覆盖初稿，不能代表当次全部 Provider 成本。

第二次单独授权 smoke 使用另一全新测试账号和合成文本验证修正：普通 MiniMax-M3 AI Run completed，只有 1 条 passing OOC，没有改写、失败重试或诊断产物；高风险确定性旁路再次 completed 且没有 Provider Token。专用 Playwright 1/1 通过。该结果证明本地合成产品链路可完成，但不构成真实用户流量、生产模型或合规批准，也不改变本报告的隐私、冻结 test 或 G2 结论。

因此本报告记录的是“候选仍可继续尽调”，不是“候选被淘汰”，也不是生产模型选择结论。

## 4. 分供应商证据与判断

### 4.1 阿里云百炼 / qwen-turbo

官方《数据安全》页面明确写明不会将客户数据用于模型训练，并说明传输数据使用 AES-256 加密。2026-09-02 生效的《阿里云百炼服务协议》进一步约定：

- API 或类似系统对接同样受协议约束；
- 客户上传、存储、加工、下载、分发或以其他方式处理的数据均为客户业务数据，客户拥有完全控制权；
- 阿里云及授权合作伙伴只按协议和客户进一步有记录的指示处理、且不为自身目的处理，或为履行法律法规／主管部门要求而处理；
- 除执行服务要求外，不进行未授权的使用和披露；客户可自行删除或更改，备份受法律与技术限制时可能延后删除，但会限制进一步处理；
- 对话数据只保留在提供服务所必需的最短时间，未经客户授权不会用于训练模型；
- 服务结束或欠费后的缓冲期由具体专有条款、产品文档或服务说明决定，届满后删除客户业务数据及缓存／备份副本；
- 客户业务数据在客户选择的百炼服务及模型所在国家或地区处理。选择境外服务可能构成数据出境，合规责任需由客户履行。

隐私与训练用途的公开承诺在三家中最明确，但固定保留天数、当前实例地域、qwen-turbo 的公开单价和具体限流仍然缺失。

型号风险同样是硬阻塞：官方文本模型目录已经把 `qwen-turbo` 放入“旧版模型”，并写明不再作为首选推荐。它仍有 128k 上下文和兼容能力说明，但这不等于长期供货、SLA 或迁移窗口承诺。若改用 qwen3.8 系列等当前推荐型号，必须作为新的 `provider＋model` 重新跑 dev，旧 qwen-turbo 结果不得沿用。

### 4.2 DeepSeek / deepseek-v4-flash

当前官方模型与价格页仍列出 `deepseek-v4-flash`，版本为 DeepSeek-V4-Flash-0731，说明其在审查日仍是公开在售型号。

公开隐私政策显示，其适用范围内会收集 Prompt、上传文件、照片、反馈和聊天历史等 User Input，并可用于改进服务以及训练和改进机器学习模型与算法；用户拥有退出使用个人数据训练模型或优化技术的权利。保留期按提供服务及政策所列目的所需，并可因合同、法律、合法商业利益、安全、稳定和争议处理继续保留。政策还称数据直接在中华人民共和国收集、处理和存储。

但该政策同时明确说明：开发者使用开放平台服务开发的下游系统或应用，其最终用户个人数据处理规则不受此政策覆盖。这一排除条款决定了上述训练、退出、保留和地域描述都不能直接当作言行最终用户 API 数据的合同保证。

生产前必须取得适用于 DeepSeek API 和下游最终用户数据的服务条款或 DPA，至少明确 Prompt／Output 是否训练、默认与可选退出机制、具体保留天数、日志及滥用检测数据、删除机制、分包处理、控制者／处理者角色、存储地域与跨境安排。

### 4.3 MiniMax / MiniMax-M3

MiniMax API 隐私政策于 2026-03-30 更新并生效，控制方为 Nanonoble Pte. Ltd. 及其关联方。政策明确会处理 Services Input & Output，包括文本、语音或其他内容以及其中的个人信息。

政策称不会用输入个人数据推断个人特征，也不会使用个人数据进行“为了画像或定向消费者”的训练。该限定语不能推导出所有 API Prompt／Output 均不用于模型训练。政策还允许在去标识或匿名化后形成用户数据库，并基于研发的合法利益进行挖掘、分析和商业利用。

政策没有固定保留天数，只称在必要、法律允许或实现收集目的所需期间保留，并在期限届满后删除或匿名化。主政策称数据存储于美国数据中心，并可能传输至用户居住国以外；安全措施示例包括 HTTPS、SSL 和 AES。

因此 MiniMax 的公开商业参数完整，但隐私条款仍不足以支持发送真实用户聊天。生产前必须取得 API 输入／输出训练用途、匿名化后二次利用、固定或上限保留期、删除时限、日志与分包处理的书面承诺。

3. 确认进入冻结 test 的最终候选、预算、报告路径和“一次运行、不自动重试”的执行规则。
4. 经产品负责人单独明确授权后，才运行 48 条冻结 test。
5. 合并 dev、test、盲标、稳定性、成本和供应商政策，提出主生成、主校验与可选降级建议；由产品负责人确认后创建新的策略版本。
