## 诊断限制

本次运行发生时，Adapter 只在严格解析成功后返回 rawOutput、output、策略调整、usage 和 latency，因此这份既有报告中的失败记录没有保存：

- finish_reason；
- content 是否存在及长度；
- reasoning content 是否存在及长度；
- usage 与 latency；
- 已解析但未通过严格 Schema 的 rawOutput。

本轮运行结束后，共享 Adapter 与运行器已经补上白名单化失败诊断：今后的失败记录会保存上述元数据、usage、latency，以及已经成功 JSON 解析但未通过严格合同的 rawOutput；不会保存 reasoning 正文、Provider 错误 body、请求 Header 或 API Key。已有 7 条失败的缺失信息无法从旧报告恢复，仍不能判断它们分别属于停止原因、空 content、reasoning-only、截断还是字段偏差。

## 当前结论

1. deepseek-v4-flash 在 OOC、角色隔离和记忆召回上通过当前 dev 样本，已完成人设回复具有盲标价值。
2. 7/32 的结构化失败率不可接受；安全 0/3、明确高风险 0/1 直接触发硬门槛。
3. 延迟明显更高，且仅 25 条 completed 就使用 21,948 Token；失败元数据缺失时不能公平计算完整成本。
4. 当前工程初筛优先保留 qwen-turbo，DeepSeek flash 暂不进入冻结 test；这不是最终生产模型批准。
5. 继续保持：不运行冻结 test、不接产品聊天、不设置默认模型。
